# Troubleshooting

Every failed HTTP response is mapped to a typed exception by `src/Transport/ResponseValidator.php`. Each exception exposes the HTTP status, the connection name, an extracted error message (redacted), and — where Azure sends one — the `x-ms-request-id`/`Request-Id` response header, which is the fastest way to correlate a failure with Azure support or the Portal's activity log.

| Exception | HTTP status | Likely cause | Fix |
|---|---|---|---|
| `BadRequestException` | 400 | Malformed request body/params — often a stale `api-version` after the `ApiVersion` enum change (see [UPGRADING.md](../UPGRADING.md)), or an invalid payload shape sent to a data-plane endpoint (Foundry/OpenAI). | Read `$message`/`$requestId` from the exception; check the payload shape against [`docs/api-reference.md`](api-reference.md) for that Request class. |
| `AuthenticationException` | 401 | AAD client-credentials token missing/expired, or issued for the wrong audience — e.g. reusing a token cached for the ARM audience against a Key Vault call. | Verify `MICROSOFT_AZURE_TENANT_ID`/`CLIENT_ID`/`CLIENT_SECRET` for the connection in use, and that the app registration's secret hasn't expired. Tokens are cached per [`TokenAudience`](../src/Enums/TokenAudience.php) (`arm`, `key_vault`, `graph`, `kudu`, `cognitive_services_data_plane`, `foundry_data_plane`, `function_runtime`, `log_analytics`, `sql`, `storage_data_plane`) via the connection's `cache_driver` — clear that cache store if a secret was recently rotated. |
| `AuthenticationException` on Storage Queue (Shared Key) | 401 or 403 | Stale/incorrect account key, or clock skew (Shared Key signing includes `x-ms-date`). | Re-fetch the account key via `storageAccounts(...)->account($name)->listKeys()`; confirm the server clock is in sync; or switch to the Entra ID (default) path instead, which needs the `Storage Queue Data Contributor` RBAC role. See [Storage](usage/storage.md). |
| `ForbiddenException` | 403 | The service principal lacks the RBAC role needed for the call — missing `Storage Queue Data Contributor`, missing `Contributor` on the subscription/resource group, or missing an enrollment-account billing role for subscription-alias creation. | Grant the appropriate Azure RBAC role at the correct scope. For billing/subscription-alias operations specifically, grant **Enrollment account subscription creator** (or equivalent) — see [Testing → Billing scope setup](testing.md#billing-scope-setup) for how to find the billing scope ID. |
| `NotFoundException` | 404 | Wrong resource name/ID, wrong resource group/subscription, or a `get()` called before a preceding `createOrUpdate()` finished provisioning. | Double-check IDs/names/casing. If this follows a create call, use `awaitProvisioningState()`/`awaitAsyncOperation()` (see [Advanced usage](advanced.md)) instead of polling manually before the resource exists. |
| `ConflictException` | 409 | Resource already exists with conflicting state (duplicate deployment name, queue already exists), or a provisioning operation is already in progress. | Prefer `createOrUpdate` semantics where the gateway offers them instead of a plain `create`; check current resource state before retrying. |
| `RateLimitException` | 429 | Azure ARM/data-plane throttling, or the package's own client-side rate limiter (`rate_limit.enabled`) tripped. | The built-in Saloon retry (`retry.*` config) already backs off automatically and honors `Retry-After` — confirm `retry.enabled=true`. If it's the client-side `rate_limit` gate that's tripping, raise `rate_limit.allow`/`rate_limit.per_seconds` or disable it. See [Configuration](configuration.md). |
| `RequestException` (generic 4xx) | other 4xx | A client error not specifically mapped above. | Inspect `$message`/`$requestId`; consult the Azure REST API doc link cited for that surface in [`ENDPOINTS.md`](../ENDPOINTS.md). |
| `MicrosoftAzureException` (base, unmapped/5xx) | 5xx or other | Azure-side outage or transient failure. | Rely on `retry.*` config for automatic backoff/retry; if persistent, check [Azure Service Health](https://azure.status.microsoft/) for the affected region. |
| `DeploymentFailedException` | n/a — thrown by `DeploymentsResource`, not `ResponseValidator` | An ARM template deployment (`deployments(...)->createOrUpdate()` / `->await()`) reached a terminal `Failed` provisioning state. | Inspect the deployment's `properties.error`, surfaced via `DeploymentData`. This mirrors what you'd see in the Portal's deployment operations blade. |
| `LongRunningOperationException` | n/a — thrown by `HandlesLongRunningOperations` | Either (a) the polled resource/async-operation reached `Failed`/`Canceled`, or (b) polling exceeded `timeoutSeconds` without reaching a terminal state. | For (a), inspect the underlying resource's error. For (b), the operation may just be slow — raise `timeoutSeconds` on `awaitProvisioningState()`/`awaitAsyncOperation()`, or call it again to keep polling. See [Advanced usage](advanced.md). |
| Config values silently not applied (cache lifetime, request timeout) | n/a | The documented config-key drift — see [Configuration → Known drift](configuration.md#known-drift-cache-lifetime--request-timeout). | Only `cache_driver`, `tenant_id`, `client_id`, `client_secret`, `subscription_id` per-connection, plus top-level `retry.*`/`rate_limit.*`/`debug.capture_bodies`, are currently wired up. |

## Redaction

Error messages surfaced by these exceptions pass through `src/Security/Redactor.php` before being included in the exception's `$message`. Successful-response bodies are **not** redacted the same way — see [Limitations](limitations.md) before turning on `debug.capture_bodies` for any surface that can return credentials (e.g. Foundry connections).
